# Grid-editable Payee is a third, on-demand writer to `merchant_name`, breaking ADR-0012's import-time-only rule

ADR-0011 and ADR-0012 established `merchant_name` as a single field with exactly two writers — the Merchant dictionary's keyword match and a Categorization Rule's rename action — both firing once, at Import time only, and never retroactively reapplied to existing Transactions. That invariant let every downstream consumer assume a Transaction's `merchant_name` is stable outside of a fresh Import.

The power-user Transactions grid redesign adds direct inline editing of Payee (Monarch-style), which writes `merchant_name` on a single Transaction at any time, not just at Import — a third writer, and the first one that isn't import-time-only. We chose to allow this deliberately: a user should be able to correct or personalize a payee name on the spot without waiting for a dictionary/rule match, same as they can already hand-edit Memo (`description`) or Category today. To keep it from quietly reshaping the Merchant dictionary's behavior, the edit also offers (with explicit user confirmation) adding the Transaction's full raw `description` as a new dictionary keyword — but that dictionary write is scoped to *future* imports only, never retroactive, preserving ADR-0012's no-retroactive-rematch guarantee for everything except this one new, explicit, user-confirmed entry point.

Future readers of ADR-0012 should not assume `merchant_name` is import-time-only anymore — it now also has a live, per-Transaction manual override path from the Transactions grid.
