# Tags are a first-class, many-to-many entity on Transactions, not a Category extension or free-text field

Monarch's rule engine can "add tags" to matching transactions, and tags there are independent of category (a transaction can carry a category plus multiple tags simultaneously, and tags are managed on their own). PesantMoney had no tagging concept in schema or services before this decision — `categorization_rules` assigns exactly one `category_id` per rule, and `Category`/`Category Group` is the only existing label taxonomy.

We considered three shapes for a minimal Tag: (1) a denormalized free-text column on `transactions` (e.g. a comma-separated string), (2) folding tags into the existing `Category`/`Category Group` hierarchy as a second kind of group, or (3) a first-class `tags` table joined to `transactions` many-to-many. A free-text column is cheap but forecloses querying/filtering by tag and invites inconsistent spelling with no dedup. Folding into `Category` conflates two different semantics — a Transaction has exactly one Category but Monarch's tags are explicitly multi-valued and orthogonal to categorization — and would violate the existing "Category: belongs to a Category Group" one-parent model. We chose a first-class `tags` table plus a `transaction_tags` join table, mirroring the existing `categories`/`category_groups` convention (simple lookup table, `created_at`/`updated_at`, referenced by id) but many-to-many instead of many-to-one, since that's the smallest model that matches Monarch's actual documented behavior (multiple tags per transaction) without inventing new conventions.

Scope for v1 is deliberately narrow: tags are created ad hoc (create-if-not-exists) wherever they're assigned — via the categorization rule action, or a manual tag picker on a transaction — rather than through a dedicated Tags management screen. A standalone tags CRUD/list screen (rename, delete, merge, filter transactions by tag) is left for a future issue once real usage shows what's needed; this keeps the rule-action feature from ballooning into a full tagging subsystem before anyone uses it.
