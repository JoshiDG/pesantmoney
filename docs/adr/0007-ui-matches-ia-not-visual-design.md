# Match Monarch's information architecture, not its visual design

The original goal was "same UI as Monarch but better." We interpreted this as matching Monarch's proven UX structure (sidebar navigation, dashboard-first layout, inline-editable transaction grid, budget-as-spreadsheet) rather than cloning its visual design (color palette, iconography, exact component styling). Closely replicating a commercial product's look-and-feel carries real trade-dress/copying risk for an open-source project and also structurally caps how "better" the result can be — an original visual design is what gives room to actually improve on Monarch rather than just polish a copy. This is a deliberate scope boundary: contributors should not treat Monarch screenshots as a pixel-accuracy spec, only as a reference for structure and interaction patterns.
