# UI conventions are synthesized from legacy desktop HIGs, not a modern platform's

ADR-0007 already commits us to an original visual design rather than cloning Monarch's — this ADR decides what that original design draws on. Rather than adopting a single modern platform's guidelines (Apple HIG, GNOME HIG), which would make the app read as "native-ish" on one OS and foreign on the other two we ship to (Tauri targets macOS/Windows/Linux), we draw interaction and structural conventions from six historical systems chosen for documented design rigor rather than platform allegiance: IBM CUA (menu/mnemonic/dialog conventions), the 1987 Apple Human Interface Guidelines (the ten principles, Edit-menu ordering, dialog layout), NeXTSTEP (anti-modality stance, verb-phrase button labels, window tiering), BeOS/Haiku (window taxonomy, reserved keyboard shortcuts), QNX Photon (informs the redesign's restraint, though its documentation turned out to have no stated UX philosophy — see `docs/research/legacy-ui-guidelines.md`), and BlackBerry 10/Cascades (interaction philosophy only — flow, content-first hierarchy — since its gesture/touch conventions don't transfer to a desktop pointer-and-keyboard app). Full sourcing, direct quotes, and confidence levels for every claim live in `docs/research/legacy-ui-guidelines.md`; this ADR only records the decision to synthesize from that material, not the specific rules — those live in `docs/ui-guidelines.md` and evolve independently of this ADR.

Modern dark-mode support and accessibility expectations override any of these legacy conventions where they conflict — none of the six source systems predate or address either — but this precedence isn't spelled out as a formal rule in the style guide; it's left to implementer judgment. Existing visual identity elements (the serif/paper/ledger aesthetic in `App.css`) aren't blanket-kept or blanket-replaced by this decision — each element is evaluated against the synthesized conventions individually as the style guide is drafted and applied. This redesign is scoped to eventually cover all 11 existing screens, not just new features, tracked as follow-on work from this ADR.
