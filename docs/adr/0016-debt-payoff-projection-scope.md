# Debt payoff projection: manual APR/payment inputs, single-account v1, avalanche/snowball deferred

Monarch's "Pay Down Goals" bring multiple debt Accounts together with APR, a chosen avalanche/snowball prioritization order across all of them, and a projected debt-free date. We're adding a narrower first version instead of the full multi-account optimizer.

APR is a new optional manual field on debt-type Accounts (credit card, loan), entered and edited by the user like any other Account attribute — never fetched from a bank or rate-lookup API. This follows the same reasoning as ADR-0003 (investment accounts, no live pricing): rate data that would require a network call is out of scope for this offline-only app, so it's a local, editable field with no "as of" staleness concept because there's nothing to go stale.

Projected debt-free date requires knowing a forward-looking payment amount, which no existing data models today — Transaction history records what happened, not a committed future payment plan. Rather than infer this from past average payments (fragile — one large or skipped payment would swing the projection wildly), the projection takes a manually-entered hypothetical monthly payment as an explicit input, separate from Goal progress tracking. This is a deliberate, narrow exception to Goal's "progress is derived, not a separate input" principle: it applies only to the *projection* (a recomputed-on-demand what-if calculator), never to progress itself, which remains balance-paydown-only per the existing Goal semantics. If the entered payment doesn't cover accruing interest, the projection has no finite payoff date and the UI must say so explicitly rather than showing a misleading or infinite number.

Avalanche/snowball prioritization is inherently a multi-account concept — it orders payoff across several debts, which is a meaningfully larger feature (cross-account allocation of a total payment budget, re-ranking as balances change) than a single account's amortization math. V1 ships single-account payoff projection only: pick a debt Account, see its projected debt-free date given its APR and a hypothetical payment. Multi-account avalanche/snowball prioritization is left to a follow-up issue once single-account projection ships and its formula/UI are validated.
