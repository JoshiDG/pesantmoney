# Hidden Transactions get their own boolean flag, not the Transfer-linking mechanism

Monarch's Transaction Rules can "hide the transaction altogether" on match. PesantMoney already excludes Transfers from income/expense reporting, so the two mechanisms could plausibly be unified. We chose not to: Transfer exclusion works by *linking two specific Transactions* in a `transfers` table (validated as an opposite-amount pair across two Accounts) and computing exclusion from that link at query time. Hiding is a *single-Transaction, rule- or user-triggered* state with no pairing semantics — forcing it through the Transfer-linking table would mean fabricating a fictitious link partner, which is a worse fit than a plain boolean.

We therefore add a `hidden` boolean directly on Transaction, reversible by the user independent of whatever rule (if any) set it. Hidden Transactions are excluded from income/expense/budget/report totals the same way linked Transfers are (both represent "don't count this"), and are excluded from the default Transactions list view behind a "Show hidden" toggle, matching Monarch's documented behavior — this is a *stronger* exclusion than a Transfer, which stays visible in the list and is only excluded from totals. Categorization Rules gain a `hide` action (alongside the existing category-assignment action) that sets this flag on match.
