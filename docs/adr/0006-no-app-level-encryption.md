# No app-level database encryption; rely on OS disk encryption

Considered encrypting the local SQLite file at rest (e.g. via SQLCipher, passphrase-gated) versus leaving it plaintext and relying on the OS's own disk encryption (FileVault/BitLocker). Chose plaintext: it keeps the database directly inspectable for debugging, support, and third-party tooling (a value for an open-source finance app), and avoids passphrase-recovery UX problems (a lost passphrase would mean unrecoverable financial history, which is a worse failure mode than the risk being mitigated). This assumes users protect the machine itself; it is not a defense against a lost/stolen unlocked laptop or another OS user account. Revisit if the community wants an opt-in encrypted mode later — retrofitting is a real migration for anyone with an existing plaintext database, so this isn't free to reverse.
